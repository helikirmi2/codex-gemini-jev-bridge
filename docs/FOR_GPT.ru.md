# Инструкция для другого чата GPT / Codex

[English](FOR_GPT.md) | [Русский](FOR_GPT.ru.md)

Этот документ передаёт контекст новому помощнику без исходной переписки, аккаунтов автора и личных путей.

## Готовый запрос

Скопируйте в новый чат, приложив этот репозиторий или дав доступ к его локальной папке:

> Помоги установить и использовать Gemini + Jev Bridge из этого репозитория. Прочитай README.ru.md, docs/USER_GUIDE.ru.md, docs/FOR_GPT.ru.md и AGENTS.md. Сначала проверь доступные локальные инструменты и текущую конфигурацию, затем выполни разрешённые действия. Gemini должен работать только через включённую квоту подписки Google AI Pro через Antigravity CLI: useG1Credits=false, без Gemini API, дополнительных кредитов и платного запасного маршрута. Jev использует мой отдельный ключ TypeSafe; не проси вставлять секреты в чат. Содержательную рутину делегируй Gemini, Jev используй для узких проверок и выбора, а планирование, применение изменений, тесты и итоговый ответ оставь за собой. Перед установкой покажи конкретные изменения, особенно общие ограничения Antigravity CLI. Если доступа к локальному компьютеру нет, дай инструкцию и прямо укажи, что сам ничего не запускал.

## Определите среду

Обычный веб-чат без доступа к локальным файлам и MCP не может установить этот stdio-сервер или проверить его на компьютере пользователя. Не изображайте выполнение команд. Не превращайте локальный сервер в публичный HTTP-сервис в обход ограничений среды.

В Codex или другом локальном MCP-клиенте найдите инструменты `gemini-jev`. Если они доступны, сначала вызовите `bridge_status`. Не запускайте повторную установку только потому, что это новый чат. Локальный статус не подтверждает действительность ключа, Google-вход или остаток квоты.

## Установка с нуля

1. Проверьте разрешения и инструкции текущего проекта, Node.js 22+, npm и Antigravity CLI. При необходимости сверяйтесь с официальной документацией, указанной в README.
2. Выполните `npm ci --ignore-scripts` и `node setup.mjs`. На Windows при блокировке `npm.ps1` используйте `npm.cmd`.
3. Настройте локальный `settings.json`. Не копируйте личные пути из чужого примера и не выбирайте модель, которой нет в аккаунте. Ограничьте `sourceRoots` нужными проектами. Ключ хранится в игнорируемом файле или окружении.
4. Вход Google требует действий владельца аккаунта. Не извлекайте OAuth-токены, cookies или пароли, не выводите ключи в логи.
5. Выполните офлайн-тесты и `node smoke.mjs --local-only`.
6. Получите конкретный план через `node install.mjs`. Учтите, что `--apply` меняет настройки Codex и **глобальный профиль CLI Antigravity**, включая ограничения ручных сессий. Следуйте полномочиям, которые пользователь уже дал для установки; не запрашивайте одно и то же согласие повторно.
7. После применения и перезапуска клиента выполните один живой тест, если обращения к сервисам уже разрешены. Сообщите, какие проверки были локальными, а какие использовали сервисы. Не приписывайте старому тесту проверку текущего состояния.

## Делегирование задач

Для `delegate_task` передайте самостоятельную задачу, минимальный контекст, только явно выбранные абсолютные пути и 1–6 проверяемых критериев. Пример аргументов без файлов:

```json
{
  "task": "Подготовь краткую инструкцию по предоставленному описанию функций.",
  "context": "Функция normalizeLabel удаляет пробелы по краям; пустой ввод возвращает пустую строку. Функция countLabels считает непустые строки после нормализации.",
  "files": [],
  "review_checks": [
    "Инструкция описывает обе предоставленные функции.",
    "Не добавлены неподтверждённые функции или обещания запуска тестов."
  ]
}
```

Инструмент возвращает `result_file`, короткий `preview`, `verdict`, оценки Jev и статистику Gemini. При необходимости читайте только относящиеся к задаче части файла. Черновик и патч — непроверенные данные; применяйте их обычными инструментами с соблюдением инструкций проекта и выполняйте подходящие тесты.

Для `jev_evaluate` объединяйте независимые узкие вопросы в один запрос. У `choice` задайте минимум два варианта и вариант недостаточности доказательств там, где он нужен. `noul` оценивает вероятность утверждения, `score` — положение на упорядоченной шкале; это не взаимозаменяемые типы. Пример:

```json
{
  "context": "Исходный документ: поддерживается только чтение CSV. Черновик: приложение также редактирует XLSX.",
  "files": [],
  "questions": {
    "support": {
      "type": "choice",
      "instructions": "Подтверждает ли исходный документ утверждение черновика о редактировании XLSX?",
      "criteria": {
        "supported": "Утверждение явно подтверждено.",
        "contradicted": "Исходный документ противоречит утверждению.",
        "insufficient": "Данных недостаточно."
      }
    }
  }
}
```

## Ограничения и завершение

- Численные оценки Jev — рекомендации. `checks_passed` не разрешает публикацию, удаление, развёртывание или слияние изменений.
- При `needs_codex_review`, ошибке сервиса или недостатке доказательств разбирайте результат сами. Не называйте его проверенным Jev, если проверка не состоялась.
- Не делегируйте простейшие команды, не дублируйте целиком одну работу у нескольких моделей. Для детерминированных операций используйте скрипты.
- Не отправляйте ключи, файлы авторизации, посторонние личные данные и целые журналы. `.gitignore` защищает публикацию, но не очищает содержимое произвольных файлов или текста запроса.
- При ошибке авторизации или исчерпании квоты сообщите о ней один раз. Остановите вызовы этого сервиса до устранения причины; продолжайте полезную разрешённую работу доступными средствами.
- Не включайте дополнительные кредиты, Gemini API или платный обход даже для исправления теста. `useG1Credits=false` обязательно.
- В итоговом ответе перечислите конкретные изменения и фактически выполненные проверки. Не обещайте фиксированную экономию лимита Codex.
